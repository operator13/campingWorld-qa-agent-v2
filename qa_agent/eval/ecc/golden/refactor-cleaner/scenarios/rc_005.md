# Scenario: Near-duplicate functions with minor differences

## Task
Analyze these two retry functions for consolidation opportunities.

## File: qa_agent/utils/http_client.py
```python
import time
import httpx

def retry_get(url: str, max_retries: int = 3) -> httpx.Response:
    """GET with exponential backoff."""
    for attempt in range(max_retries):
        try:
            resp = httpx.get(url, timeout=10)
            resp.raise_for_status()
            return resp
        except httpx.HTTPError:
            if attempt == max_retries - 1:
                raise
            time.sleep(2 ** attempt)

def retry_post(url: str, payload: dict, max_retries: int = 3) -> httpx.Response:
    """POST with exponential backoff."""
    for attempt in range(max_retries):
        try:
            resp = httpx.post(url, json=payload, timeout=10)
            resp.raise_for_status()
            return resp
        except httpx.HTTPError:
            if attempt == max_retries - 1:
                raise
            time.sleep(2 ** attempt)
```

## Expected Finding
`retry_get` and `retry_post` share identical retry/backoff logic. The
only difference is the HTTP method and the payload argument. Merge into
a single `retry_request(method, url, *, payload=None, max_retries=3)`
function or use a generic wrapper.
