# Scenario: Fix flaky test - timing issue on dynamic content

## Task
Fix the following flaky Playwright test that intermittently fails in CI.

## Error
```
Error: expect(received).toHaveText("3 items in cart")
  Received: "0 items in cart"
  at cart.spec.ts:18:42
```

## Flaky Test Code
```typescript
// cart.spec.ts
import { test, expect } from '@playwright/test';

test('cart count updates after adding items', async ({ page }) => {
  await page.goto('/products/tent-pro-3000');
  await page.getByRole('button', { name: 'Add to Cart' }).click();
  await page.goto('/products/sleeping-bag-comfort');
  await page.getByRole('button', { name: 'Add to Cart' }).click();
  await page.goto('/products/camp-stove-xl');
  await page.getByRole('button', { name: 'Add to Cart' }).click();

  await page.waitForTimeout(500);
  const cartCount = page.getByTestId('cart-count');
  await expect(cartCount).toHaveText('3 items in cart');
});
```

## Root Cause
The `waitForTimeout(500)` is not sufficient. The cart count is updated
via an async API call after each "Add to Cart" click. On slow CI runners
the response has not arrived by the time the assertion runs.

## Expected Fix
Replace `waitForTimeout` with a proper auto-wait assertion or wait for
the network response to complete before asserting.
