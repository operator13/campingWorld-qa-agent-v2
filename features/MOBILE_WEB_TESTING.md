# Feature: Mobile Web Testing

> Test web apps on mobile viewports — starting with Playwright device emulation (cheap, fast) and optionally graduating to real Mobile Safari on the Xcode iOS Simulator.

**Status:** PARTIALLY DONE (emulation profiles in playwright.config)
**Priority:** Medium
**Depends on:** Core framework (Phases 0-4)

---

## The Problem

Mobile users are often >50% of traffic. Responsive layout bugs, touch-specific interactions, and mobile-only flows (hamburger menus, swipe gestures, viewport-dependent logic) are invisible to desktop-only tests.

## The Solution

Two tiers:
1. **Tier 1 (cheap):** Playwright device emulation — runs in CI, cross-platform, covers responsive layout + touch events
2. **Tier 2 (deep fidelity):** Real Mobile Safari on Xcode iOS Simulator — covers Safari-specific rendering bugs, only on macOS runners

---

## A. Current State

The `playwright.config.ts` generated by the Executor already includes mobile projects:

```typescript
projects: [
  { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
  { name: 'mobile-chrome', use: { ...devices['Pixel 7'] } },
  { name: 'mobile-safari', use: { ...devices['iPhone 15'] } },
],
```

This gives viewport emulation and touch event simulation out of the box. What's missing is mobile-*aware* test generation and real-device testing.

---

## B. What Mobile Tests Should Cover

| Category | Desktop test | Mobile-specific adaptation |
|----------|-------------|---------------------------|
| Navigation | Click top nav links | Open hamburger menu first, then tap links |
| Forms | Fill and submit | Handle mobile keyboard, autocomplete, zoom-on-focus |
| Touch interactions | Click | Tap, long-press, swipe, pinch-to-zoom |
| Responsive layout | Full-width elements | Stacked layout, hidden sidebar, scroll behavior |
| Viewport-dependent | Always visible | Conditionally rendered elements (mobile-only CTAs) |
| Orientation | N/A | Portrait vs landscape behavior |

## D. Assumptions

- Tier 1 (emulation) is the default and works everywhere.
- Tier 2 (real Safari) is opt-in and only for macOS runners.
- Device list is configurable per project — not every app needs iPad testing.
- Touch events in emulation mode are sufficient for most responsive testing.
- Native app testing (Swift/Kotlin) is out of scope — this is web apps only.

## E. Not in Scope

- Native iOS/Android app testing (Appium, XCTest, Espresso)
- Real physical device farms (BrowserStack, Sauce Labs)
- Performance profiling on mobile devices
- PWA-specific testing (service workers, offline mode)
